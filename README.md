# 贪吃蛇 + PPO（自写环境）

**前三个例子的环境和奖励都是官方给的。这个是第一个「自己写环境和奖励」的。**

**算法部分一个字没改** —— 换掉的只有 `env = gym.make("Acrobot-v1")` → `env = SnakeEnv()`。

最后停在 **18 维状态 + 8×8 网格，终测 50 局平均 59.12 个豆（满分 61），34/50 局打满**。

---

## 一、最快看到效果（不用训练）

本目录里已经有一份训练好的 `snake_both.pth`（18 维，终测 59.12 个豆）：

```bash
uv run python watch.py            # 开窗口看它自己玩（默认就加载这份）
uv run python record.py           # 或者出一张胶片图，不用开窗口
```

> ⚠️ `.pth` 是训练产物，`.gitignore` 里不入库（和 `acrobot/` 一样）。
> **所以重新 clone 出来是空的，要先自己训一次。**

**只想花 17 秒看个大概**，就跑 12 维的快速版：

```bash
uv run python ppo.py                    # 约 17 秒，生成 snake_best.pth（12 维，23.7 个豆）
uv run python watch.py snake_best.pth
```

窗口里留意三件事：

1. 它是不是**直奔豆子** —— 而不是随机游走
2. 蛇长了之后，**怎么绕开自己** —— 这才是这个游戏真正的难点
3. 被自己堵住时会不会**提前转向**留空间 —— 这是状态里 flood fill 那几维在起作用

## 二、从零训练

```bash
uv run python ppo.py                            # 12 维（约 17 秒）
uv run python ppo.py --deep --tail --out snake_both.pth    # 18 维，最强那版（约 39 分钟）
```

`--deep` / `--tail` / `--no-space` 三个开关**任意组合**，用来做状态特征的消融：

| 开关组合 | 状态维度 |
|---|---|
| 默认 | 12 |
| `--deep` | 15 |
| `--tail` | 15 |
| `--deep --tail` | 18 |
| `--no-space` | 9 |

> ⚠️ **`--deep` 和 `--tail` 都是 15 维，但特征顺序不同** ——
> 所以 `ppo.py` 把环境配置和权重**存在同一个文件里**，
> `watch.py` / `record.py` 读 checkpoint 自带的配置来建环境。
> 光看维度猜是猜不出来的，猜错了不会报错，只会**静默玩得很烂**。

### ⭐ 四路特征消融（本机实测，终测 50 局）

| 状态 | checkpoint | 平均豆 | 中位 | 最好 | 最差 | 主要死因 | 用时 |
|---|---|---|---|---|---|---|---|
| 12 维（只 30 批早停）| `snake_best` | 23.70 | 23 | 34 | 16 | 咬自己 38 · 撞墙 12 | 17 秒 |
| 12 维（长训练）| `snake_long` | 34.84 | 34 | 55 | 19 | 咬自己 44 · 撞墙 6 | 9 分钟 |
| 15 维 **+2 步前瞻** | `snake_deep` | 42.78 | 43 | 61 | 20 | 咬自己 39 · 通关 4 | 25 分钟 |
| 15 维 **+蛇尾可达** | `snake_tail` | 56.74 | 58 | 61 | 16 | 咬自己 15 · 通关 14 | 33 分钟 |
| **18 维（两个都加）** | **`snake_both`** | **59.12** | **61** | **61** | **37** | **通关 34** · 咬自己 11 | 39 分钟 |

**三条结论：**

**① 「蛇尾可达」这 3 维比「2 步前瞻」那 3 维值钱得多。**
同样是在 12 维基础上加 3 维，一个 +22 豆（34.84 → 56.74），一个只 +8 豆（34.84 → 42.78）。

**② 死因分布比平均分更能说明问题。**

```
12 维：咬自己 44 / 撞墙 6                  ← 自陷是绝对主因
18 维：通关 34 / 咬自己 11 / 饿死 4 / 撞墙 1   ← 主因从「死」变成「通关」
```

**③ 计算成本和价值不成正比。**

```
蛇尾可达：obs_dim ×1.25，每步 BFS 成本 ×1.18  →  +22 豆
2 步前瞻：obs_dim ×1.25，每步 BFS 成本 ×3.46  →   +8 豆
```

> ⚠️ **这不是严格的等预算对照，看数字时得留个心眼。**
> 四路的**特征和训练量是同时变的** —— 步数从 330 万 → 390 万 → 790 万，
> 豆子数也跟着从 34.84 → 42.78 → 59.12 涨。
>
> 所以这张表能回答的是「**这套特征最终能到哪**」，
> **回答不了**「同样步数下哪套特征更强」。
> 想把两件事分开，得固定步数再跑一轮（见最后一节）。

### ⭐ 四条线放一起（12 维那一版）

| | 平均豆子 | 平均步数 | 每豆步数 | 主要死因 |
|---|---|---|---|---|
| 随机策略 | **0.16** | 13.8 | — | 撞墙 50/50 |
| 朴素贪心（只看 1 格）| **17.84** | 118.4 | 6.64 | 咬自己 43 / 撞墙 7 |
| **PPO（12 维）** | **23.70** | 179.0 | 7.55 | 咬自己 38 / 撞墙 12 |
| 贪心 + 空间（**能看全盘**）| **24.04** | 193.6 | 8.05 | 咬自己 36 / 撞墙 14 |

> **PPO 只靠 12 维特征，追平了能看全盘的手写规则 AI**（差 0.34 个豆，1.4%）。
>
> 📌 **死因很说明问题**：连能看全盘的手写 AI 都有 **36/50 死于「咬自己」**。
> 8×8 上自陷才是主要死法，不是撞墙。

## 三、为什么自己写一个环境

`insights.md` #25 里写着：

> **奖励是唯一能操控的旋钮 —— 但前三个例子里，那个旋钮一直是别人在拧。**

自写环境的价值在于：**状态和奖励的设计权拿回来了，然后你会发现坑全在这里。**

**算法部分一个字没改**：

```python
compute_gae(...)             # 和 lunarlander / acrobot 逐字相同
ppo_update(...)              # 同上
collect_trajectories(...)    # 同上
```

> **「算法是通用机器，你写的只是环境和奖励」—— 这次真的验证了。**

## 四、状态和奖励是怎么设计的

### 状态（9 ~ 18 维，按开关拼装）

**基础 9 维（永远都在）：**

```
[0:3]  左 / 直 / 右 三格是什么    0=空  0.5=墙  1=身体
[3]    食物相对蛇头的【前后】    -1/0/1
[4]    食物相对蛇头的【左右】    -1/0/1
[5]    到食物的曼哈顿距离 / (2(W-1))
[6]    饥饿计数 / MAX_HUNGER
[7]    当前长度 / (W*W)
[8]    蛇头到蛇尾的曼哈顿距离 / (2(W-1))
```

**三组可选特征（每组 3 维，下标都和动作 0/1/2 一一对齐）：**

```
[9:12]   use_space  走这个动作【之后】还剩多少可达空格数 / (W*W)     ← flood fill
[12:15]  use_deep   走 a 之后，下一步【最差】还剩多少空间 / (W*W)    ← 2 步前瞻
[15:18]  use_tail   走 a 之后，蛇头能不能走到蛇尾              0/1  ← 蛇尾可达
```

| 特征 | 一句话 | 见过的数 |
|---|---|---|
| `[9:12]` | 「这一步走完，我还剩多少地方可去」| 50 / 64 = **0.7812** |
| `[12:15]` | 「走完这步，**最坏**再走一步还剩多少」| 49 / 64 = 0.7656 或 **0** |
| `[15:18]` | 「走完这步，我还追得到自己的尾巴吗」| **0 或 1** |

三个设计要点：

**① `[3][4]` 是蛇头坐标系，不是屏幕的上下左右。**
跟着朝向旋转，策略才能和"蛇朝哪边"无关。

**② 三组特征的下标都和动作 `0/1/2` 对齐**，让"这个动作会给我留下什么"是网络**可以直接读**的。

**③ `[12:15]` 取的是 min，是防守型特征 —— 宁可误报，不可漏报。**
它表达的是"最坏情况有多坏"，不是"平均有多好"。

**为什么必须有 flood fill？** 因为 1 格视野只能避免「立刻死」，避免不了「走进死胡同」：

> `[0:3]` 在「左边是空地」和「左边那条通道被身体堵死」时输出**完全一样**。

**为什么「蛇尾可达」最值钱？** 因为它是**经典安全判据**：

> 只要能追到自己的尾巴，就可以一直跟着尾巴走 —— **永远不会被围死**。
> 追不到，说明自己已经把自己圈进了一个封闭区域。

**这引出了一个关键区分：**

| | 说明 |
|---|---|
| **表示障碍** | 信息**不在输入里** —— 网络再大再久也学不出来 |
| **优化障碍** | 信息在，但**学得慢** —— 加网络、加训练量能解决 |

`“下一步会进死胡同”` 属于前者：`[0:3]` 里根本没有这个信息。
`“该先绕一圈去吃更近的豆”` 属于后者。

> 📎 判据：**如果这个量在输入里压根不存在，那就别指望训练解决它。**

### 奖励

```python
吃到豆          +1.0
撞墙 / 咬自己    -1.0   terminated
饥饿超时         -1.0   terminated
其他每步          0.0
```

**每局必然以 −1 结束，所以「评估分 = 豆子数 − 1」。**

**「活得久」没有单独写进奖励** —— 靠 `MAX_HUNGER`（太久没吃到豆就判死）**间接**激励。

> ⚠️ **绝对不要加「每步 −0.01」这类密集惩罚**，那会让**主动送死变成最优解**：
> ```
> 绕 100 步饿死：  -1(饿死) - 1.00(100步)  = -2.0
> 10 步撞死：      -1(撞死) - 0.10         = -1.1   ← 更划算
> ```
> 📎 这就是 `insights.md` #25 里那条「油费 ×100 → 直接摔」的**同一个数学**。

## 五、⭐ 自写环境踩到的坑

**自写环境最大的特点是：gymnasium 本来帮你免掉的那些坑，现在全归你了 —— 而且都不报错。**

每条都在 `snake_env.py` 的 `__main__` 里配了断言（**共 53 条**）。

### 坑 1 · 差点抄错的 `ret_scale`（最险的一个）

原本打算照抄 `acrobot/ppo.py`，它有一行：

```python
critic_loss = nn.MSELoss()(values.squeeze(-1), returns[mb]) / ret_scale
ret_scale = returns.std() ** 2 + 1e-8
```

那是为 Acrobot 的 **−500 量级**回报设计的配平。**蛇的回报是 O(1)**（吃到 N 个豆 → 回报 N−1，std ≈ 0.3），除下去等于把 critic loss **放大 10 倍**。

更糟的是开局：一批全是「10 步撞墙，−1」，`returns.std() ≈ 0` → **除以 `1e-8` → 梯度爆炸**。

而它和 actor **共用主干** → 通过公共参数把 actor 也带崩。

✅ **改用 `lunarlander` 的 SepNet（actor/critic 各一套主干）+ 不缩放。**
分开主干之后，谁大谁小都淹不到对方（`insights.md` #26）。

### 坑 2 · 尾巴腾格（最阴的一个）

**非进食时尾巴会移开，所以「头进入尾格」是【合法】的。**

如果 obs 的安全格用「格子在身体集合里 → 不安全」，而 `step` 用「移动后的占位」，
两者就不一致 —— **状态在撒谎，value 永远学不会**（而且不报错）。

而且**长蛇急转弯的能力全部来自这一条规则**，判错直接影响上限。

✅ 抽出唯一的 `_simulate_from(body, direction, food, action)`，**obs / step / flood fill / 2 步前瞻 / 手写 AI 全调它**。
自测里跑 300 局 × 每步 3 个动作，断言「危险码 ⇔ 真的会死」，**矛盾 0 次**。

### 坑 3 · 左右镜像 180°

动作映射（左转/右转）和食物方位编码（前/后、左/右）**各写一遍旋转逻辑**的话，
很容易一个顺时针一个逆时针 —— **静默镜像 180°**。

PPO 理论上能学回来，但要烧掉几十万步，而且你 debug 时**完全看不出**。

✅ **只写一份 `turn_left` / `turn_right`**，然后用一个断言锁死两个坐标系是同一个：

```python
# 把食物放到「动作 0（左转）会进入的那一格」
assert obs[3] == 0     # 前后：不是前面也不是后面
assert obs[4] == -1    # 左右：左边  ✅
```

这一条同时验证了**动作映射、旋转方向、食物编码**三者对齐。

### 坑 4 · obs 必须是新数组

`collect_one_trajectory` 是 `states.append(state)` —— **存的是引用**。

如果 `_get_obs()` 复用同一个缓冲区，**整批训练数据会变成最后一帧**，而且不报错。

✅ 每次新建 `np.zeros(obs_dim)`，自测里断言 `not np.shares_memory`。

### 坑 5 · `reset(seed=...)` 没真的播种

`evaluate()` 用的是 `env.reset(seed=seed+i)` 跑「固定种子贪心评估」。
如果环境不认种子，**每次评估都是不同的 20 局** → 分数噪声 → **达标判据完全失效**。

✅ `reset` 第一行 `super().reset(seed=seed)`，随机数一律走 `self._rand()`。

### 坑 6 · 分数单位

每局必然以 −1 结束 → **评估分 = 豆子数 − 1**。

写达标线时如果不换算，会写出「10 分」其实是「11 个豆」这种线。

✅ `ppo.py` 的打印里两个单位都写清楚，`info` 里带 `food_eaten` 和 `end_reason`。

### 坑 7 · 界面文字全是豆腐块 `□□□`

**这条不在环境里，在渲染层，同样「不报错」。**

```python
pygame.font.match_font("PingFang SC")     # macOS 上返回 None
```

PingFang **压根不在 pygame 能枚举出来的字体表里**，于是静默退回
`SysFont(None)` → FreeSans → **所有中文变成豆腐块**，一声不吭。

✅ **先按文件路径直接找，找不到再按名字找**（`snake_env.find_cjk_font()`）。

> 📌 **同一个坑的另一半：中文字体里没有 emoji 字形。**
> 标题里写 `🎉 满分通关` 会渲染成豆腐块，写 `★ 满分通关` 就正常。
> **能用和不能用，都是"看起来像乱码但程序不报错"** —— 和前面六条是同一类问题。

## 六、训练时最该盯的一行

```python
best = max(traj_scores)      # 本批最好 = 吃到的豆子数 - 1
```

蛇的奖励是**稀疏**的，所以这一列比"平均分"重要得多：

| 现象 | 说明 | 该怎么办 |
|---|---|---|
| 200 批过去 `best` 还是 −1.0 | **一次都没吃到过** | 这是**探索问题** —— 别乱调学习率 |
| `best > −1` 但均分不涨 | **信用分配问题**（+1 离前面 50 步太远）| 该上塑形（PBRS）了 |
| 均分涨了但贪心评估不涨 | **两把尺子**（`insights.md` #14）| 看熵、看 clip |

**12 维那一版的实测**：

```
  🍎 第 1 批：【第一次吃到豆子】 本批最好 +1.0（= 2 个豆）

   10 |   10127 |      6.91 |     18.0 |     14.25 | 达标 1/3
   20 |   42839 |     15.31 |     27.0 |     16.25 | 达标 2/3
   30 |   89470 |     22.09 |     31.0 |     23.40 | 达标 3/3
```

**第 1 批就吃到豆子了** —— 因为 8×8 很小，随机漫游也能撞上。这也是选小网格的原因。

> ⚠️ **别在训练早期下结论。** 这次 15 维那一路跑到第 40 批时看着"没什么用"，
> 到第 400 批却是 42.78 个豆。**早期批次说明不了最终结果。**

## 十、这次回答了什么

> **把奖励和状态的设计权拿回来之后，会踩什么坑？**

前面三个例子都回答不了这个问题 —— 因为它们的奖励和状态**不是你写的**。

这次的答案：

| 坑 | 后果 |
|---|---|
| 抄错一个超参（`ret_scale`）| 回报量级不匹配 → 梯度爆炸 |
| 尾巴腾格规则写两遍 | **状态撒谎** → value 永远学不会 |
| 左右旋转写两遍 | **静默镜像** → 烧几十万步才学回来 |
| obs 复用缓冲区 | **整批数据变成最后一帧** |
| `reset` 不认种子 | 评估变成随机 → **判据失效** |
| 字体只按名字找 | **中文全变豆腐块**，不报错 |

**六条全是"不报错"的。** 这就是自写环境和用现成环境的区别 ——
现成环境里这些都被作者踩过一遍了。

**第二个问题是：加特征到底有没有用？**

| | 结论 |
|---|---|
| **有用，但要看加的是哪个** | 「蛇尾可达」+22 豆，「2 步前瞻」只 +8 豆 |
| **计算成本不值当正比** | 蛇尾可达成本 ×1.18，「2 步前瞻」成本 ×3.46 |
| **死因分布比平均分更说明问题** | 12 维是「咬自己 44」，18 维变成「通关 34」 |
| **表示障碍 ≠ 优化障碍** | 信息不在输入里的，加网络加训练量都没用 |
